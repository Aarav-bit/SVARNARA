## 2024-07-23 - Proper ARIA Tab Pattern Implementation
**Learning:** When implementing tabbed interfaces, just adding `role="tab"` and `aria-selected` is not enough for screen readers and keyboard users. A fully accessible W3C ARIA tab pattern requires `aria-controls` linking to a `tabpanel`, explicit `tabIndex` management (only active tab is focusable with `0`, others `-1`), and keyboard event handlers (left/right arrows) to shift focus intuitively between tabs.
**Action:** Always implement explicit keyboard navigation (`ArrowLeft` / `ArrowRight`) and manage `tabIndex` alongside `aria-controls` and `aria-labelledby` when building custom tab components to ensure they are fully navigable and descriptive for assistive technologies.
## 2024-05-24 - Custom Button Keyboard Scrolling Issue
**Learning:** Custom UI elements that use `role="button"` and handle `onKeyDown` for accessibility can cause unintended page scrolling when users press the Space key. This occurs because Space is the default browser shortcut for scrolling down. When using custom handlers for keyboard interactions, we need to explicitly prevent this default behavior to maintain an accessible and expected experience.
**Action:** When implementing custom interactive elements like custom buttons with `onKeyDown` handlers for Space and Enter, always ensure to call `e.preventDefault()` for those keys to prevent the browser's default behavior, especially unintended page scrolling.
